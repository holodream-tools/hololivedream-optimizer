# hololive Dreams 隊伍最佳化

幫你從持有的卡片裡找出最強的五人隊伍，並計算指定歌曲的預估分數。

**▶ https://holodream-tools.github.io/hololivedream-optimizer/**

不用註冊、不用安裝。所有計算都在你自己的瀏覽器裡跑完，卡片庫存也只留在這台裝置上，不會上傳到任何地方。

---

## 怎麼用

### 1. 設定你有哪些卡

到「**我的卡片**」，勾選你實際擁有的卡，設定每張的**命座**，並把可用的 **Leader Outfit** 打開。

幾個省時間的做法：

- 上方的批次按鈕作用於「目前篩選出來的卡」，所以可以先選期生或屬性，再一次全設
- 右上角可切換三種檢視：**清單**（選卡最快）、**卡片**、**卡片＋技能**
- 設定好之後按「**匯出**」存成 JSON 備份，換裝置或清瀏覽器資料時可以「匯入」還原

### 2. 找最強隊伍

到「**隊伍最佳化**」按下計算。它會把所有可能的五人組合 × 所有已解鎖的 Leader Outfit 全部算過一遍，不是抽樣、也沒有跳過任何一種。

- **指定必須上場的卡**：想用某張推し卡的話，先把它鎖定，剩下的空位交給計算補齊。鎖得越多算得越快
- **同一組隊伍只顯示最佳 Leader**：預設開啟，避免同一支隊伍配不同 Leader 佔滿排行
- **略過只差一張卡的相似隊伍**：想看更多樣的組合時打開
- **顯示筆數**：5 到 30 之間自己調，改了立刻反應，不用重算

每一列點「**這個數字怎麼來的**」可以展開，看這支隊伍的分數是怎麼算出來的。

### 3. 算指定歌曲的分數

到「**歌曲／順序**」，先選一支剛才算出來的隊伍，再選歌。

它會列出該譜面的 **Perfect-FC 預估分**，並把 120 種站位全部試過、挑出最好的那個——因為五個 Special 的發動時間是譜面固定的，誰站在哪一格會改變覆蓋到的音符。

### 其他

- 「**卡片庫**」可以查任何一張卡在各命座下的能力值與技能敘述
- 「**自選隊伍**」可以自己挑五張試算，並看到分數的組成明細

## 注意事項

### 這個分數不是遊戲裡的分數

「推薦指數」是**隊伍之間的相對比較值**，用來排名，不對應遊戲畫面上的任何數字。它把總合力和技能期望值合成一個可比較的量，好回答「A 隊和 B 隊哪個強」，但不回答「這隊能打幾分」。

要看接近實際的分數，請用「歌曲／順序」——那裡用的是公開譜面的真實音符與 Special 時間點。

算法的每一步寫在 [分數是怎麼算的](#分數是怎麼算的)。

### 模型沒有納入的東西

- **Board、Connect、Memory、Fever** — 目前沒有公開的結構化資料可用
- **玩家失誤** — 兩種模式都假設 Perfect Full Combo
- **Combo／Life 條件的技能** — 泛用模式一律用基礎值（沒有譜面就無法判定）；指定歌曲模式會用真實連段數
- 泛用模式的 **Special 以 192 秒參考長度換算成時間平均**，不是真實歌長

所以算出來的排名適合當**參考方向**，不該當成精確保證。

### 資料可能落後遊戲

卡片數值與技能是社群整理的公開資料，新卡上線後可能要等一段時間才會出現，也可能與遊戲內有出入。

譜面資料是打包在網站裡的，新歌需要等網站更新才會有。

### 你的庫存存在哪裡

存在**這台裝置的瀏覽器**裡（localStorage）。這代表：

- 換瀏覽器、換裝置、用無痕視窗 → 看不到你的設定
- 清除瀏覽器資料 → 設定會消失

**建議設定完就按「匯出」存一份 JSON。**

### 圖片

卡片圖與成員立繪都是**直接引用原始發布位置**，本網站沒有存放任何圖片檔。如果來源網站變更或無法連線，圖片會消失，但功能完全不受影響——卡片會改用文字與屬性色顯示。

### 計算會吃 CPU

完整搜尋的計算量很大（例如 66 張卡 × 66 個 Outfit 就是 5.9 億次評估）。計算期間會用到多個執行緒，筆電可能會發熱、風扇轉動。可以隨時按取消。

## 分數是怎麼算的

### 推薦指數（隊伍最佳化用的）

從五張卡的能力值開始，一步一步疊上去：

**① 基礎能力** — 每張卡在你設定的命座下的 Lv.80 三圍（Performance／Technique／Sense），五張加總。

**② Passive** — 依「總能力由高到低」的順序套用。每個效果**各自**向上取整，不是先把百分比加總再算一次：

```
Cute 屬性中能力最高的 2 人的 Technique +41%
→ 那 2 人的 Technique 各自 × 1.41 後無條件進位
```

**③ Leader Outfit** — 條件成立才生效，同樣逐效果進位。
其中「全員 Score Support +X%」是**整隊一個光環，只算一次**，不會因為隊上有五個人就變成五倍。

**④ Special** — 泛用模式沒有指定歌曲，所以把五個 Special 的效果換算成整首歌的平均值：

```
Special 貢獻 = Σ (score_support × 持續秒數 ÷ 192)
```

192 秒是明確標示的**參考長度**，不宣稱是實際歌長。

**⑤ Active 平均效果** — 每張卡先算它「平均有多少比例的時間在生效」：

```
覆蓋率 = min(1, 發動機率 × 持續秒數 ÷ 判定間隔)
```

然後——**這裡是關鍵**——多張卡的 Active 重疊時，遊戲只採用**最強的那一個**，不是相加。所以要算的是「實際生效的最大值」的期望：

```
先把效果由強到弱排序，然後
E[最大值] = Σ  效果ₖ × 機率ₖ × Π(1 − 機率ⱼ)   ← j 是所有比它強的效果
```

意思是：只有當所有更強的效果都沒發動時，這個效果才會成為當下最強的那個。

**⑥ 合成**

```
Active 倍率 = Active期望 ÷ 100 × (1 + (Passive支援 + Outfit支援 + Special支援) ÷ 100)
推薦指數    = 加成後總合力 × (1 + Active 倍率)
```

注意 **Score Support 本身不加分**。它只出現在括號裡，作用是**放大正在生效的 Active**——沒有 Active 發動的瞬間，再高的 Score Support 也不會產生分數。這是本工具與部分其他計算器最主要的模型差異。

### 指定歌曲的預估分

有了譜面就不必用平均值，可以照真實時間點算：

**① 每個 PERFECT 的基礎分**

```
PERFECT 基礎分 = floor(加成後總合力 ÷ 該譜面的分數除數)
```

分數除數取自 [Hololive Dreams Lab](https://dreams.wf-calc.net/simulator) 的逐譜面估計值。

**② 逐音符累加** — 一般音符用基礎分、中間音符用 `ceil(基礎分 × 0.1)`，再乘上該音符自己的權重。

**③ 每個音符當下的加成** — 檢查那一刻有哪些 Special 視窗覆蓋著（提供 Score Support）、哪些 Active 正在生效，一樣用上面的「取最強」期望公式算出倍率。

**④ 站位** — 五個 Special 的發動時間由譜面固定，誰站在第幾格決定了誰的 Special 蓋在哪一段。五個人有 120 種排法，全部算過再挑分數最高的。

這個數字仍然是 **Perfect Full Combo 且滿 Life** 的模型估計，不含玩家失誤，也不是官方保證值。

## 開發

```bash
npm install
npm run dev      # 開發伺服器
npm test         # 與 Python 參考實作的對照測試
npm run build
```

計算引擎是從一份 Python 實作移植過來的，兩邊由對照資料鎖在一起：泛用模式的指數要求逐位元相同、切分後的 Top-N 要與單執行緒版本完全一致、譜面分數在 78–2022 音符全範圍相符。測試沒過代表兩份實作走偏了，`npm run build` 之前會先擋下來。

`public/data/` 的資料由本機的 Python 專案（未公開）匯出，`tools/` 底下是匯出腳本。一般開發不需要這一步——資料已經在版本控制裡了。
