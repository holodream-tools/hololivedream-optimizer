# hololive Dreams 隊伍最佳化

從你持有的卡片裡找出最強的五人隊伍，並計算指定歌曲的預估分數。

**▶ https://holodream-tools.github.io/hololivedream-optimizer/**

免安裝、免註冊。所有計算都在你的瀏覽器裡完成，卡片庫存只留在這台裝置，不會上傳。

<br>

## 怎麼用

**1 · 我的卡片** — 勾選持有的卡、設定命座、開啟 Leader Outfit。

> 批次按鈕只作用於「目前篩選出來的卡」，先篩選再批次最快。
> 右上可切換**清單／卡片／卡片＋技能**三種檢視。
> 設定完請按批次列右側的**匯出**，存一份備份（見下方「備份與換裝置」）。

**2 · 隊伍最佳化** — 按下計算，把所有五人組合 × 所有 Leader Outfit 全部算過一遍。

> **指定必須上場的卡**：想用某張卡就先鎖定，剩下空位交給計算，鎖越多算越快。
> **顯示筆數**：5–30 之間隨時調，不用重算。
> 點**這個數字怎麼來的**可以展開分數組成，也會列出**條件技能有沒有觸發**。條件沒滿足的技能一分都不會加，這裡會直接寫還差什麼，例如「需要 Pure ≥2，目前只有 1」。

**3 · 歌曲／順序** — 選一首歌，用實際譜面算分。有兩種模式：

> **指定隊伍**——算你挑的那一隊，在這首歌能拿幾分。
> **歌曲最佳化**——不管你原本挑誰，直接找出這首歌最適合的隊伍。通用最強的那一隊，打某一首歌時常常不是最強的。
>
> 五個 Special 的發動時間由譜面固定，誰站哪一格會蓋到不同的音符，所以兩種模式都會把 120 種排法試過一遍。
> 下面還會畫出**技能時間軸**，看得到哪個技能落在音符密集的地方、哪些技能撞在一起。

**4 · 隊伍比較** — 在排名列或自選隊伍按「比較」，兩隊送進 A / B 並排對照。

> 每一列都標出哪一隊較高，但兩邊的原始數值與差距都保留。
> 兩隊只差一張卡（或只差隊長服裝）時，頁面會直接給出這次替換的分數差。
> **差異歸因**會告訴你 A 為什麼贏 B：把總差距拆成基礎能力、Passive、Outfit、Active、SAR、各項 Score Support，每一項貢獻多少一目了然，而且加起來剛好等於總差距。

**分享隊伍** — 在自選隊伍頁按**複製分享連結**，網址就帶著這五張卡、隊長服裝和命座。對方就算一張都沒有，打開看到的分數也跟你一樣。連結不會帶到你的持有清單。

另有**卡片庫**（查各命座的能力值與技能）與**自選隊伍**（自己挑五張試算）。

### 備份與換裝置

你的設定只存在**當下這台裝置的這個瀏覽器**裡，不會同步到別的地方。所以下列情況都會看到空白的庫存：

- 換一台裝置（電腦 → 手機）
- 同一台裝置換瀏覽器（Chrome → Firefox）
- 無痕視窗
- 清除瀏覽器的網站資料

持有卡、命座、自選隊伍的五人與隊長、最近看的歌曲和顯示設定都會自動存起來，下次打開就會回到原樣。算出來的結果（排行榜、時間軸、歸因）不會存，重算一次就有。要清掉的話，「我的卡片」批次列右側有**清除已儲存設定**。

要帶著走就用「我的卡片」批次列右側的兩個按鈕：

| | |
|---|---|
| **匯出** | 下載 `hololive-dreams-my-cards.json`，內含你的持有、命座、Leader 設定 |
| **匯入** | 選擇該檔案還原。匯出檔涵蓋全部卡片，所以匯入等於**完整取代**目前的設定——不能用多份檔案合併庫存 |

## 注意事項

| | |
|---|---|
| **綜合推薦指數不是遊戲分數** | 它是用於隊伍強弱比較的估算指標，非實際 Live 分數：回答「哪隊比較強」，不回答「能打幾分」。它以 Generic 192 秒模型快速比較大量隊伍；要看分數請用「歌曲／順序」，那裡才依實際譜面、Combo、Special、Active、SAR 的時間點計算。 |
| **未納入** | Board、Connect、Memory、Fever、玩家失誤。兩種模式都假設全 PERFECT。 |
| **庫存存在瀏覽器** | 換裝置、換瀏覽器、清除網站資料都會消失。**請匯出備份。** |
| **圖片是外部引用** | 本站不存放圖片檔。來源失效時圖片會消失，功能不受影響。 |
| **資料可能落後** | 卡片資料為社群整理，新卡可能延遲；譜面需等網站更新。 |
| **計算吃 CPU** | 完整搜尋可達數億次評估，計算期間裝置負載會升高，可隨時取消。 |
| **歌曲最佳化不是全部算過** | 它是從通用排名前面幾組隊伍裡挑出最好的，不保證是所有隊伍裡的第一名。詳見下方說明。 |

## 分數是怎麼算的

### 綜合推薦指數

| | 做什麼 |
|---|---|
| **1 · 基礎能力** | 五張卡在所選命座下的 Lv.80 表現力／技巧／品味，加總 |
| **2 · Passive** | 同一人同一項參數收到的百分比先相加，再乘卡片**原始值**一次 |
| **3 · Outfit** | 條件符合才生效，一樣乘**原始值**；「全員 Score Support」整隊只算一次 |
| **4 · Special** | `Σ (score_support × 持續秒數 ÷ 192)` |
| **5 · Active** | `覆蓋率 = min(1, 發動機率 × 持續秒數 ÷ 判定間隔)` |
| **6 · 合成** | `綜合推薦指數 = 總合力 × (1 + Active倍率)`<br>`Active倍率 = Active期望 ÷ 100 × (1 + 各項Support ÷ 100)` |

> 第 4 步的 192 秒是固定的參考長度，不是實際歌長——這個模式本來就不知道你要打哪首歌。

### 為什麼跟其他工具算出來不一樣

同一支隊伍，不同工具給的數字常常對不起來。差異幾乎都出在這三個地方：

**Score Support 本身不會加分。** 它的作用是放大**正在生效的** Active——Active 沒發動的那些時間，Score Support 再高也不會多出分數。技能敘述本身就是這樣寫的（「效果時間內提高 Score UP」），但把它當成獨立加成直接乘進總分，算出來會高不少。

**Active 重疊時只取最強的一個，不是相加。** 五張卡的 Active 同時生效，得到的是其中最強的那個效果，不是五個加起來。所以要算的是「當下實際生效的那個」平均有多強：

```
效果由強到弱排序後
平均效果 = Σ  效果ₖ × 機率ₖ × Π(1 − 機率ⱼ)     j = 所有比它更強的效果
```

換句話說，一個效果要成為「當下最強」，前提是比它強的都剛好沒發動。

**所有百分比都以卡片原始值為分母，不會層層相乘。** 同一人同一項參數吃到兩個 `+41%`，是 `+82%`，不是 `1.41 × 1.41 = +98.8%`；隊長衣裝的 `+135%` 也是另一個獨立加項，不是再乘上去。

這點差很多。一位成員如果同時吃到自身 `+32%` 全參數、兩個 `+41%` 技巧、再加隊長 `+130%`，兩種算法差到 1.75 倍。層層相乘會讓「單屬性高倍率隊長 ＋ 多個同屬性 Passive」的隊伍被嚴重高估，最佳化排出來的就不是最強隊伍，而是模型最會算錯的隊伍。

### 指定歌曲

| | 做什麼 |
|---|---|
| **1 · PERFECT 基礎分** | `floor(總合力 ÷ 該譜面分數除數)` |
| **2 · 逐音符加總** | 一般音符用基礎分，中間音符用其十分之一（進位），各乘音符權重 |
| **3 · 當下加成** | 看該瞬間有哪些 Special／Active 生效，同樣「只取最強」 |
| **4 · 站位** | 所有排法都算過，取最高分 |

分數除數取自 [Hololive Dreams Lab](https://dreams.wf-calc.net/simulator)。結果是「全 PERFECT 且 Life 全滿」前提下的估計值。

### 歌曲最佳化的「候選」要選哪個

歌曲模式要一個音符一個音符地算，比通用模式慢很多，沒辦法把幾百萬支隊伍全部算過。所以做法是：先用通用模式排名，再從前面幾組隊伍裡，用譜面重新算一次、重新排名。

介面上有兩個選項：

| | 什麼時候用 | 大約要多久 |
|---|---|---|
| **快速**（前 200 組） | 只想知道這首歌最強的是哪一隊 | 1～2 秒 |
| **完整 Top 10**（前 1000 組） | 想看完整的前十名 | 6～12 秒 |

實際拿 6 首風格差很多的歌測過：每一首的最強隊伍都落在通用排名前 50 名以內，所以「快速」就找得到；但前十名裡會混進通用排名 500 名以後的隊伍，想看完整前十就要用「完整 Top 10」。

> 結果是「從前面這幾組裡找出來最好的」，不保證是所有隊伍裡的第一名，畫面上也是這樣寫的。

同一批測試也發現：**通用排名第一的隊伍，打這 6 首歌時分別只排到第 22～410 名**，比各曲最強的隊伍少了 2.5%～10.9%。所以「通用最強」跟「這首歌最強」真的常常不是同一隊。

### 三種覆蓋率

技能開得久，不代表真的多拿分。所以時間軸把它拆成三個數字：

| | 意思 |
|---|---|
| **時間覆蓋** | 技能開著的時間佔全曲多少 |
| **音符覆蓋** | 這段時間內蓋到多少音符 |
| **分數覆蓋** | 那些音符實際值多少分 |

差別可以很大。KINGWORLD 上有位成員技能只開了 11% 的時間，卻蓋到 19% 的音符——但只拿到 9.8% 的分數，因為那一段都是只值十分之一的中間音符。反過來另一位開得最短，位置卻在後段（Combo 加成已經累積起來），分數反而拿最多。

### 移除影響

比較頁的「移除影響」是**假設性的計算**，不是一支真的四人隊的分數。被移除的成員完全不參與：三項能力、屬性與世代人數、他提供的 Passive、他本來會收到的 Passive、Active、Special 一律不算，剩下四人的 Passive 受益者與所有條件全部重新判定。

Outfit 本身保留——它是獨立的一格，不是第六名成員——但它自己的發動條件會依剩下四人重新判定。所以一件需要「某屬性 2 人」的 Outfit，可能因為少了那個人而整份失效，這也算進移除影響裡。

歌曲模式下，剩下四人會重跑全部 4! 種站位取最高分，再與五人的最高分相減：問的是「少了他，這隊在最佳狀態下差多少」，不是「他在原本那個為五人排好的站位裡值多少」。

因為每一項都是連鎖重算，**五個人的數字不會、也不應該加總等於總分**。

```bash
npm install
npm run dev      # 開發伺服器
npm test         # 與 Python 參考實作的對照測試
npm run build
```
